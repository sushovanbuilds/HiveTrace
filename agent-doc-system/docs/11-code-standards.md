# Code Standards

## General
- Prefer simple, readable solutions.
- Keep modules cohesive.
- Avoid speculative abstraction.
- Handle errors explicitly.

## Naming
TBD by language/framework.

## Types
Prefer strong typing and narrow interfaces.

## Functions / Components
Keep responsibilities focused; split only when it improves clarity or testability.

## Logging
Use structured logging and never log secrets or sensitive data.

## Comments
Explain intent, invariants, and non-obvious trade-offs—not obvious syntax.
